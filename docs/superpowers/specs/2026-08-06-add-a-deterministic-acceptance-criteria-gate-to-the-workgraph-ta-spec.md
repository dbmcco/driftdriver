# Add a deterministic acceptance-criteria gate to the workgraph task completion path in this repo (driftdriver). Today a task can be marked Done on agent judgment alone. Build: (1) a deterministic acceptance evaluator that checks each task's acceptance_criteria against produced artifacts before completion sticks; (2) wire it into the completion path so wg done evaluates first; (3) a degrade-to-advisory escape hatch with a CLI to inspect and reset degrade counts, where the degrade counter must have a per-repo ceiling so a broken repo cannot rack up waived gates across many tasks and lose signal in volume; (4) end-to-end verification. ## End State

A deterministic acceptance-criteria gate sits in the workgraph task completion path for driftdriver. When an agent calls wg done (or the equivalent completion directive), the gate evaluates the task's acceptance_criteria against produced artifacts before the completion sticks. The gate is hard by default: unmet criteria block completion. A degrade-to-advisory escape hatch allows downgrading a single failed gate to advisory, incrementing a per-repo degrade counter. The counter has a configurable ceiling (default 5) in drift-policy.toml; when exceeded, the gate reverts to hard mode and the operator is notified. The CLI exposes inspection (status, current count, ceiling) and reset. The pattern matches signal_gate.py: hard gate, degrade-to-advisory hatch, escalate ignored findings.

## Acceptance Criteria

- wg done <task> invokes the acceptance evaluator before marking the task Done
- Tasks with unmet acceptance_criteria are blocked from completion by default
- The degrade-to-advisory escape hatch is invocable per-task and increments a per-repo counter
- The per-repo degrade counter has a configurable ceiling (default 5) in drift-policy.toml
- When the degrade ceiling is exceeded the gate reverts to hard mode and cannot be degraded further without a reset
- CLI commands exist to inspect degrade status (count, ceiling, mode) and reset the counter
- Tasks without acceptance_criteria in their contract pass through the gate without blocking (backward compatible)
- Unit tests cover evaluator pass/fail, degrade counter increment, ceiling enforcement, reset, and passthrough for tasks without criteria
- Integration tests cover end-to-end completion path with gate blocking, degrade flow, ceiling trip, and reset
- The gate implementation matches the signal_gate.py pattern (hard gate + degrade + escalate)

## Out Of Scope

- LLM-based semantic evaluation of artifacts (deterministic/structural checks only in this phase)
- Changing how acceptance_criteria are authored or structured in task contracts
- Retroactively re-evaluating already-completed tasks
- Modifications to the wg binary itself (all work is in driftdriver's Python layer and hooks)
- Cross-repo or fleet-wide degrade ceiling aggregation (per-repo only in this phase)

## Risks

- Gate is too strict and blocks legitimate task completions that agents expect to finalize [high]: Degrade-to-advisory escape hatch allows per-task downgrade; tasks without acceptance_criteria pass through; ceiling prevents systemic abuse.
- Per-repo degrade ceiling is set too high, allowing signal loss across many waived gates [medium]: Default ceiling is conservative (5); configurable in drift-policy.toml; when exceeded, gate reverts to hard mode and operator is notified.
- Evaluator cannot deterministically verify artifact semantics (e.g., 'the function is correct' is not structurally checkable) [medium]: Initial evaluator uses structural checks only (file existence, pattern match, command exit code, checkbox state); semantic evaluation deferred to a future phase; malformed or uncheckable criteria produce a clear error, not a silent pass.
- Wiring into wg done breaks existing task completion for the 22 blocked and 8 done tasks already in the workgraph [high]: Backward-compatible passthrough for tasks without acceptance_criteria; integration tests verify existing completion path still works; feature-flag fallback if wiring cannot preserve compat.
- Degrade counter persistence is lost on reboot or session restart, resetting the ceiling protection [medium]: Counter persists to .workgraph/acceptance_degrade_state.json mirroring the persistence mechanism used by signal_gate.py; discovery node confirms and matches that mechanism.
